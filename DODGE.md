# Уворот, прицельная стрельба и плавное движение

Форк PylaAI. Бот выполнял 1.5 функции из 3: ходил, стрелял автоприцелом, не уворачивался.
Здесь добавлены недостающие полторы.

| Функция | Было | Стало |
|---|---|---|
| Передвижение | есть, рывками по 8 направлениям | плавное скольжение, резкое **только** в уворот |
| Атака | 0.5 — автоприцел, стреляет туда, где враг **был** | упреждение: решается уравнение перехвата |
| Уворот | 0 | детект снарядов + выбор направления с минимумом попаданий |

Плюс то, чего не было вовсе: определение **границ карты** (модель стен их не видит)
и криминалистический лог, отвечающий на вопрос «почему по нему попали».

## Быстрый старт

Плейстайл уже выбран в `cfg/bot_config.toml`. Бот запускается как обычно —
`start_pyla.bat` сам активирует venv, где лежит CUDA:

```bash
start_pyla.bat
```

Посмотреть, что видит детектор — включи `debug_view = true` в `cfg/debug_settings.toml`.

Разобрать, почему бот словил урон:

```bash
venv\Scripts\python.exe tools\dodge_report.py --detail
```

Проверить детектор на записи, не заходя в бой:

```bash
venv\Scripts\python.exe tools\dodge_tune.py запись.mp4 --out размеченное.mp4
```



Уворот физически не может жить целиком в `.pyla`: плейстайлу доступны только боксы,
и вызывается он 10–20 раз в секунду. Снарядам нужны пиксели, история кадров и полный
фреймрейт scrcpy. Поэтому:

```
движок (Python)                        плейстайл (.pyla)
─────────────────                      ──────────────────
находит снаряды        ──projectiles─▶ решает: уворачиваться или добивать
считает их скорость                    выбирает архетип и дистанцию
меряет границы карты   ──map_boundary─▶ куда не идти
ведёт врагов           ──aimed_attack─▶ когда стрелять с упреждением
                       ◀──movement─────  выдаёт вектор
                       ◀─sharp_movement─ плавно или резко
```

**Вся тактика — в одном `.pyla`.** Движок — только глаза и руки.

### Модули

| Файл | Роль |
|---|---|
| `dodge/tracker.py` | компенсация камеры, разность кадров, блобы, треки снарядов |
| `dodge/solver.py` | геометрия: попадёт ли, и куда отойти при нескольких снарядах |
| `dodge/aim.py` | скорость врагов в мировых координатах + уравнение перехвата |
| `dodge/motion.py` | границы карты и упор, измеренные по поведению камеры |
| `dodge/smoothing.py` | плавное скольжение джойстика и резкий байпас |
| `dodge/palette.py` | цветовая модель террейна (статика + адаптация под карту) |
| `dodge/service.py` | фоновый поток на полном фреймрейте + аварийный перехват джойстика |
| `dodge/logbook.py` | лог решений для разбора полётов |

## Уворот: как выбирается направление

Хитбоксы — круги, а не точки, поэтому «отойти на пиксель» не работает: нужно вынести
из линии огня `радиус игрока + радиус снаряда + запас` (53 + 18 + 12 ≈ 83 px).

Каждый кадр перебираются 16 направлений плюс «стоять». Для каждого решается,
столкнётся ли **каждый** снаряд с движущимся игроком:

```
|rel_pos + rel_vel·t| = R_игрока + R_снаряда
```

Стоимость направления = сумма по всем угрозам (чем скорее попадание, тем дороже)
+ штраф за стену + штраф за границу карты + отклонение от тактики.
Выбирается минимум — **то самое «куда меньше всего попаданий»**.

Уворот держится `commit_time` (0.14 с), иначе два равноценных варианта чередуются
каждый кадр и бот трясётся на месте.

### От чего увернуться нельзя — и это правильно

Чтобы уйти, нужно `d ≥ R + v_снаряда · (R / v_игрока)`. При R=83 и скорости бойца 330 px/s:

| Скорость снаряда | Минимальная дистанция |
|---|---|
| 700 px/s (Барли, Дайнамайк) | ~260 px — уворот работает |
| 1700 px/s (Кольт) | ~510 px — только на дальней дистанции |
| 3000 px/s (в упор) | невозможно |

Бот не будет имитировать уворот там, где он бесполезен: солвер сравнивает с вариантом
«стоять» и, если движение не лучше, продолжает тактику. В логе это `IMPOSSIBLE`.

## Прицельная стрельба

Кнопка атаки — это стик: тап отдаёт выстрел автоприцелу (бьёт туда, где враг уже был),
а протяжка целится вручную. Бот тянет стик в решённую точку.

Твоя формула `V·T=S` реализована как уравнение перехвата, где **T вычисляется**, а не
берётся константой:

```
(|v_врага|² − v_снаряда²)·t² + 2(rel·v_врага)·t + |rel|² = 0
```

Проверка симуляцией — выстрел действительно приходит в цель:

```
цель                          упреждение   T       промах
неподвижная, 600 px               0 px   0.231с    0.00 px
поперёк 400 px/s                 93 px   0.234с    0.00 px
поперёк 700 px/s                168 px   0.240с    0.00 px
сближается 500 px/s              97 px   0.194с    0.00 px
убегает 500 px/s                143 px   0.286с    0.00 px
в упор 120 px                    18 px   0.042с    0.00 px
```

Фиксированные 0.3 с промахивались бы на 27–53 px. На ближней дистанции правильное
упреждение почти ноль, на дальней — сильно больше 0.3 с.

**Скорость врага меряется в мировых координатах, не экранных.** Экранная скорость
загрязнена панорамой камеры: в тесте враг шёл 300 px/s, камера ехала 240 px/s, и на
экране он «полз» 60 px/s. Прицел по экранной скорости ошибался бы на **256 px/s**.

Скорость снаряда — общая для всех (`aim.projectile_speed = 2600`), потому что в
`brawlers_info.json` таких данных нет. Для Кольта/Пайпер занижена, для Барли завышена;
если играешь одним бойцом — подстрой.

## Границы карты

Модель стен работает хорошо, но **край арены она не видит** — там нет спрайта стены.
Определяется по камере: у границы камера перестаёт панорамировать, а персонаж
съезжает с центра экрана. Куда съехал — там и край.

Порог намеренно высокий (17% экрана ≈ 326 px по горизонтали) с гистерезисом и
требованием 4 кадров подряд: у обычной стены персонаж тоже слегка смещается, и это
не должно считаться краем карты.

Даёт три вещи: солвер не уводит в край, плейстайл туда не ходит, и появляется честный
детект упора (`is_stuck`) вместо таймерной эвристики.

## Плавное движение

По умолчанию вектор джойстика **плавно доводится** до цели (`smooth_tau = 0.16 с`),
а скорость поворота ограничена (`max_turn_rate = 520°/с`) — повороты выходят дугами.
Бот, дёргающийся между 8 направлениями, виден невооружённым глазом; ведущий дуги — нет.

В уворот всё это **обходится целиком**: сглаживание, лимит `minimum_movement_delay`
и unstuck-вращение. Стик прыгает на вектор ухода за один кадр. Контраст намеренный.

Плейстайл переключает это одной строкой:

```python
movement = decision.vector
sharp_movement = True     # ← резко
```

## Отладочное окно

`debug_view = true` в `cfg/debug_settings.toml`. Три уровня, чтобы **видеть мусор**:

| Цвет | Что это |
|---|---|
| **серые крестики** | сырые блобы после фильтра размера — уровень шума |
| **жёлтые круги** + цифра | треки с историей, ещё не подтверждённые (цифра — число кадров) |
| **малиновый круг + линия** | подтверждённый снаряд и его предсказанная траектория |
| **зелёный прицел** | точка упреждения |
| **оранжевая стрелка** | выбранное направление уворота |

Внизу строка: `blobs / rejected / tracks / confirmed / мс` и `map edge / move eff`.

Правило: если серых много при отсутствии стрельбы — подними `vision.motion_threshold`.
Если жёлтые никогда не становятся малиновыми — слишком строгие `origin` или
`tracking.min_straightness`.

## Лог: почему по боту попали

Включён (`logging.enabled = true`). Пишется в `debug_frames/dodge_log.jsonl`.

```bash
python tools/dodge_report.py --detail
```

Каждое решение получает вердикт, и каждый требует **разного** исправления:

| Вердикт | Что означает | Что крутить |
|---|---|---|
| `DODGED` | увернулся | — |
| `DETECTED_TOO_LATE` | снаряд подтверждён позже, чем нужно на уход | `min_confirm_hits` → 2, или поднять FPS эмулятора |
| `IMPOSSIBLE` | ни одно направление не спасает | не баг — позиционная проблема |
| `BLOCKED` | уходы были, но все в стену/край | `wall_penalty` ниже, либо проверить модель стен |
| `OVERRULED` | чистый уход был, но проиграл тактике | `tactical_weight` ниже |

Пример вывода:

```
[t=0.0015s] BLOCKED  tti=0.3529s  player_speed=330.0px/s
    threat #3: 700 px/s, impact in 353 ms, confidence 0.9
    stay score: 1.545
      stay       score   1.545  hits 1
          68 deg score   2.716  hits 0  wall     ← уход был, но в стену
         -68 deg score   2.716  hits 0  wall
```

## Что изменено в твоей системе

**CUDA не работала — и это была не твоя вина.** `onnxruntime-gpu 1.28` не везёт с собой
CUDA-рантайм, он ставится отдельными `nvidia-*` пакетами. Их не было, DLL не грузились,
onnxruntime **молча** откатывался на CPU, при этом печатая «Using CUDA GPU».

Установлены CUDA 13 + cuDNN 9 (`nvidia-cublas 13.6` — это и есть недостающий
`cublasLt64_13.dll`). В `detect.py` добавлен `ort.preload_dlls()` — без него библиотеки
из `site-packages/nvidia` не находятся, — и честная проверка, какой провайдер реально
работает.

Замер на RTX 3080 Ti:

```
CUDA  5.62 мс/инференс  ->  178 IPS
CPU  20.83 мс/инференс  ->   48 IPS      ускорение 3.7x
```

Прочие правки конфигов:

| Файл | Было | Стало | Почему |
|---|---|---|---|
| `general_config.toml` | `emulator_port = 5037` | `5555` | 5037 — порт ADB-**сервера**, не устройства. Совпадений не было, а у тебя три устройства онлайн, и бот выбирал произвольное |
| `bot_config.toml` | `universal_smart_v5...` | `unified_dodge.pyla` | новый объединённый плейстайл |
| `dodge_config.toml` | — | `logging.enabled = true` | чтобы было что разбирать |

> `onnxruntime-directml` и `onnxruntime-gpu` установлены оба и конфликтуют — они ставят
> один и тот же модуль. Сейчас активен gpu, что для 3080 Ti правильно. Если будешь
> переустанавливать зависимости через `setup.py`, он потянет directml и снова затрёт CUDA.

## Объединённый плейстайл

`playstyles/unified_dodge.pyla` вбирает все четыре официальных:

| Источник | Что взято |
|---|---|
| `default_up` / `default_right` | боевое дерево, супер, гаджет, hold-атака |
| `follower` | сбор с тиммейтами |
| `showdown_survivor` | ротация к центру, побег от газа |
| `universal_smart` | архетипы ASSASSIN / TANK / SNIPER / LOBS / RANGED |

Порядок приоритетов: газ → бой по архетипу → детект упора → **уворот перекрывает всё**.
Стрельба идёт независимо от движения — стик и кнопка атаки это разные пойнтеры,
поэтому бот стреляет и во время ухода.

Настройки в шапке файла:

```python
DODGE_MIN_CONFIDENCE = 0.45   # игнорировать шаткие треки
DODGE_BREAKS_SPACING = True   # уворот важнее дистанции боя
ATTACK_WHILE_DODGING = True   # стрелять во время ухода
AIMED_SHOTS = True            # упреждение вместо автоприцела
AVOID_MAP_EDGE = True         # не ходить в край карты
STRAFE_PERIOD = 2.0           # период смены стороны стрейфа
```

## Производительность

| Стадия | Стоимость |
|---|---|
| Трекер снарядов | 3.3 мс/кадр |
| YOLO (CUDA) | 5.6 мс |
| YOLO (CPU, было) | 20.8 мс |

Трекер работает в **отдельном потоке** на полном фреймрейте scrcpy, а не на частоте
основного цикла. Задержка подтверждения — 3 кадра: 100 мс при 30 FPS, 50 мс при 60 FPS.
Аварийный путь при `tti < 0.22 с` перехватывает джойстик напрямую из потока, не дожидаясь
следующей итерации YOLO.

Поднять FPS эмулятора — самое действенное, что можно сделать для уворота: задержка
детекта падает пропорционально.

## Известные ограничения

- **Скорость снаряда одна на всех бойцов** — в `brawlers_info.json` нет этих данных.
- **Рикошеты не предсказываются** (Рико, Кольт с гаджетом): траектория линейная, отражение
  от стены не моделируется.
- **Навесные атаки** (Барли, Дайнамайк) летят по дуге и приземляются в точку — линейная
  модель считает их пролетающими мимо. Уворот от них работает хуже.
- **Origin gating слеп к невидимым врагам.** Есть запасной путь (`allow_unknown_origin`),
  но он требует 5 кадров и чтобы снаряд летел прямо в бота.
- **Синтетический стенд ≠ реальная игра.** Все цифры выше получены на генерируемых кадрах.
  Прогони `tools/dodge_tune.py` на своей записи прежде, чем доверять настройкам.
